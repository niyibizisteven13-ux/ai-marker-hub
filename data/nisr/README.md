# NISR datasets

Public datasets and reports from the **National Institute of Statistics of Rwanda (NISR)** that Bwenge may cite. Bwenge does not read this folder on every question. An explicit command builds a versioned index, and answers retrieve from that index.

```
data/nisr/
  README.md        this file
  manifest.json    one entry per dataset/report (source, period, license, checksum, column mapping)
  raw/             original public files (CSV, XLSX, JSON, or extracted report text .txt/.md)
  schemas/         optional codebooks / column definitions
  index/           generated by `npm run nisr:index` (git-ignored, rebuild on deploy)
```

The manifest ships empty on purpose. No NISR numbers are bundled until someone adds a real, licensed source file.

## Adding a dataset

1. Download the public file from statistics.gov.rw (or the NISR microdata portal). Put it in `raw/` unchanged.
2. Add an entry to `manifest.json`:

```json
{
  "id": "lfs-2023-annual-unemployment",
  "title": "Labour Force Survey Annual Report 2023: unemployment rate by district",
  "organization": "National Institute of Statistics of Rwanda (NISR)",
  "sourceUrl": "https://www.statistics.gov.rw/...",
  "publicationDate": "2024-03-01",
  "referencePeriod": "2023",
  "geographicCoverage": "Rwanda, districts",
  "license": "NISR terms of use (cite source)",
  "format": "csv",
  "file": "raw/lfs-2023-unemployment-by-district.csv",
  "checksum": "",
  "units": "percent",
  "table": {
    "indicator": "Unemployment rate",
    "geographyColumn": "District",
    "periodColumn": "Year",
    "valueColumn": "Rate",
    "unit": "%"
  }
}
```

3. Run `npm run nisr:index -- --write-checksums` once. This records the file's sha256 in the manifest. Commit both the file and the manifest.
4. After that, `npm run nisr:index` rebuilds only when the manifest or a file checksum changes. If a file changes without a manifest update, the checksums no longer match. That dataset is then marked `failed` and left out of the index, never silently re-indexed.

### Table mapping (`table`)

| Field | Meaning |
|---|---|
| `indicatorColumn` / `indicator` | Column holding the indicator name, or a constant for single-indicator tables |
| `geographyColumn` / `geography` | Column holding district/province/etc., or a constant such as `"Rwanda"` |
| `periodColumn` + `valueColumn` | **Long format:** one row per period |
| `periodColumns` | **Wide format:** e.g. `["2019","2020","2021"]`. Each column is a period. |
| `unitColumn` / `unit` | Unit per row, or a constant (`"%"`, `"people"`, `"RWF billion"`) |
| `dimensionColumns` | Extra breakdowns kept with each value (e.g. `["Sex","Area"]`) |
| `sheet`, `headerRow` | XLSX only |

Reports use `"format": "text"`, with the report text extracted to `.txt`/`.md`. The text is split into citable passages. Do not commit PDFs and expect numbers from them. Extract and check the tables first.

### Data rules

- **Missing is not zero.** `..`, `-`, `n/a`, blanks and unrecognisable values are stored as `null` and reported as missing.
- Numbers like `1,234` and `12.5%` are parsed. Ambiguous forms such as `12,5` are kept as missing rather than guessed.
- Every answer and artifact carries the dataset title, organization, reference period, source URL and source row.
- File contents are untrusted data. Instructions found inside a report never change Bwenge's behaviour.

## Approval

Datasets are indexed by default. Set `NISR_REQUIRE_APPROVAL=true` to index only entries with `"status": "approved"`. Entries marked `"pending"` or `"rejected"` are always skipped.

## Re-indexing in production

- CLI: `npm run nisr:index` (or `-- --force`). Run it as part of deploy, because the index is not committed.
- Admin API: `POST /api/admin/datasets/nisr/reindex` (admin only, audit-logged) and `GET /api/admin/datasets/nisr/status`.
- Limits: `NISR_MAX_FILE_MB` (default 50) and `NISR_MAX_ROWS` (default 200000) per file.
