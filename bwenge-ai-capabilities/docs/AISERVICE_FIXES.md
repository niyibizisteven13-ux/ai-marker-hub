# Problems found in the current AiService.ts (and how the new layer fixes them)

Found by reading the file you shared; I could not run your service, so items marked "verify" depend on a helper whose code was not in the file.

1. **Inconsistent `stripThinkingTags` use (verify).** Some places use `stripThinkingTags(x).text` (a string) and others use `stripThinkingTags(rawTurnText)` directly: `runGonkaAgentLoop` sets `turnMessage.content = stripThinkingTags(rawTurnText)` and emits it as `text`. One of the two is wrong. If the function returns `{ text }`, the assistant message content becomes an object and the next request to the model fails or the UI shows `[object Object]`. Fix: always use one string-returning helper. The new layer uses `ThinkFilter`, which hides `<think>` tags even when split across chunks and emits only the new visible text (your Gonka loop handles splits by re-stripping the whole accumulated text on every token and re-sending it with `replaceFullText`, which works but is heavier; the NVIDIA and plain streaming paths do not strip at all).
2. **`streamGonkaChat` never streams.** It sends `stream: false` and parses SSE only as a fallback. Users wait for the whole answer. Fix: the new adapter requests `stream: true` and falls back to JSON only if the gateway ignores it.
3. **`streamClaudeChat` loses the answer on the Gonka path.** It returns `this.streamGonkaChat(..., { onToken: () => {} })`: tokens are discarded and the return value is `undefined`, while the Anthropic path returns a stream object. Any caller using this function gets nothing.
4. **No timeout while the stream is being read.** `fetchWithTimeout` clears its timer as soon as headers arrive (the `finally` block), so a provider that stalls mid-answer hangs the request forever in `runGonkaAgentLoop`, `streamNvidiaNimChat`, `runNvidiaAgentLoop`, and `streamOllamaChat`. Fix: the adapter has an idle timeout (default 45 s without data), and the runtime retries and emits `turn_reset`.
5. **PDF and Word uploads are decoded as UTF-8 on the Gonka path.** `Buffer.from(file.base64, 'base64').toString('utf8')` turns a PDF or DOCX into binary garbage inside the prompt. Fix: `ingestUploads` extracts real text (PDF, DOCX, XLSX, PPTX, CSV, HTML) and passes images as vision parts.
6. **Images are dropped when tools are enabled (Gonka).** The `generalAssist` branch that calls `runGonkaAgentLoop` does not pass `images`, so vision input is lost whenever tools are on.
7. **Silent fallback to another provider.** `providerAvailable('gonkarouter')` returns true when only a Gemini client exists, so if `GONKA_API_KEY` is missing, "GonkaRouter" mode quietly runs on Gemini while events are still labelled `provider: 'GonkaRouter'`. `sendGonkaChat` and `streamGonkaChat` also fall back to Gemini when the gateway fails, without telling the user. That hides outages and moves student or personal data to a different company. If that is not intended, make the fallback explicit and configurable (for example `ALLOW_GEMINI_FALLBACK=false`) and show a visible notice when it happens.
8. **Three near-duplicate tool loops that have drifted.** Gonka strips thinking tags; NVIDIA does not. `load_specialized_tool` and `analyze_data_with_python` are handled only in the Anthropic loop, so they silently do not exist for Gonka and NVIDIA. Fix: one `AgentRuntime` for all OpenAI-compatible providers (tested), with tools registered in one `ToolRegistry`.
9. **Mid-stream failures kill the whole loop.** Retries wrap only the initial `fetch`; an error while reading the stream (after the response began) is not retried, and the partially streamed text is never reset in the UI. The new runtime retries the turn and emits `turn_reset`.
10. **Recovery messages pollute answers.** Messages like "Retrying turn..." are injected as normal `text` events, so they can be saved into chat history. They are now separate `turn_reset` events.
11. **UI (`AiResponseView`).** The typewriter effect replays for every message each time the component mounts (including old messages loaded from history) and restarts from zero if the text grows during streaming; it also types one character per 12 ms, so a 3,000-character answer takes 36 seconds. The updated view takes `animate` (false for history), continues from where it was while streaming, and reveals in chunks so any answer finishes in about two seconds. "Read aloud" now uses the interface language.
